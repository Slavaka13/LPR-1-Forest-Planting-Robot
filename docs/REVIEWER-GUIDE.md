# Путеводитель проверяющего по программной части ЛПР-1

**Предполагаемое время первого знакомства:** около 10–15 минут без запуска оборудования.

## Что посмотреть в первую очередь

1. [README](../README.md) — техническое назначение, ограничения, навигация.
2. [FILE-CATALOG](FILE-CATALOG.md) — все собственные файлы, назначение, риски запуска.
3. [CONTROL](CONTROL.md) — радиопульт, режимы, управление шасси и Failsafe.
4. [PLANTING](PLANTING.md) — цикл формирования лунки и подачи семян.
5. [GPS-AND-VIDEO](GPS-AND-VIDEO.md) — треки, точки посадки, видеозапись.
6. [HARDWARE-INTERFACES](HARDWARE-INTERFACES.md) — оборудование и адреса интерфейсов.
7. [TESTING](TESTING.md) — способы проверки и ограничения доказательств.

## Соответствие требованиям кейса

| Критерий | Подтверждение в репозитории | Уровень подтверждения |
|---|---|---|
| Гусеничное управление | `rc_drive.py`, `hoverboard.py`, FOC-прошивка | Исходный код |
| Формирование лунки | `seeder.py` | Алгоритм и настройки; нужна серия испытаний глубины |
| Подача семян | `shuttle.py`, `seeder.py` | Алгоритм; нужна серия испытаний дозирования |
| Безопасная остановка | `rc_drive.py`, `hoverboard.py`, контроллер | Логика; нужна стендовая проверка |
| GPS-маршрут | `gps_log.py`, `gps_export.py` | Реализация журнала; нужны примерные данные |
| Точность интервала посадки | Частично через действия оператора | Не подтверждена автономная реализация |
| Автономная навигация | — | Не реализована |
| Автоматический обход препятствий | — | Не реализован |
| Точное измерение глубины | Модель по времени + контроль тока | Абсолютный датчик отсутствует |
| Надёжность работы на грунте | Методики в `TESTING.md` | Протоколы полевых испытаний не предоставлены |

## Быстрая безопасная проверка

В среде с Python 3 статическая компиляция модулей (без запуска моторов):

```bash
python3 -m compileall -q raspberry-pi/
```

Подробные тесты не следует запускать произвольно: сначала убедиться, что они не обращаются к реальным устройствам, и ознакомиться с их состоянием на выбранном коммите.

## Сторонние компоненты и авторство

В `firmware/source/Drivers/` расположены CMSIS и STM32 HAL — сторонние библиотеки, а не самостоятельные модули команды. Основная FOC-прошивка использует сторонний проект hoverboard; исходную лицензию и авторские уведомления нужно сохранять. Качественные утверждения о разработке должны различать модификацию существующего решения и оригинальные части ЛПР-1.

## Чего пока нет в пакете

- Фотографий и схем с подписями в README — они добавляются отдельным согласованным этапом.
- Полного воспроизводимого автоматического развёртывания на любом новом оборудовании.
- Подтверждённых числовых протоколов полевой производительности и точности дозирования.
- Проверенной калькуляции серийного изготовления и окупаемости.

Если комиссия хочет провести запуск механизмов, потребуется подготовленный стенд, оператор, средства физического обесточивания, актуальная электросхема и документирование результатов.
